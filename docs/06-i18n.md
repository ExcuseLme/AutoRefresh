# 06 · 多语言（i18n）

## 1. 机制（保留 ARP 的做法，只维护中文）

ARP 是标准 Chrome 扩展 i18n：`_locales/<lang>/messages.json` + `manifest.default_locale`，
界面文案通过 `browser.i18n.getMessage(key)` 取（popup 里封装成 `L(key)` / `t(key)`，
还带 `[参数]` 占位替换：ARP 的 `L('interval_random_summary',[String(e),String(t)])` ⇒ `每 $1–$2 秒刷新`）。

本扩展：

- `public/_locales/zh_CN/messages.json`（**唯一** locale）
- `public/_locales/en/messages.json`（**不提供**；`default_locale` 设 `zh_CN`）
- `manifest`：`"default_locale": "zh_CN"`
- 代码里统一用 `src/lib/i18n.ts`：

```ts
export function t(key: MsgKey, subs?: (string | number)[]): string {
  const m = chrome.i18n.getMessage(key, subs?.map(String));
  return m || key;   // 缺失时回退为 key，便于开发期暴露漏翻
}
```

> ARP 有一层 `L()` 兼容层同时支持"键缺失回落英文"和 `$1..$9` 替换。我们没有英文，
> 缺键就返回键名，并在 `vitest` 里加一条"所有 `t()` 用到的 key 都存在于 messages.json"的检查。

## 2. key 命名规范

沿用 ARP 的扁平 `snake_case`，按功能前缀分组（**不按组件名**，避免组件重构时改 key）：

| 前缀 | 用途 | 例 |
| --- | --- | --- |
| `app_` | 品牌 / 通用 | `app_name`、`app_status_idle` |
| `action_` | 主操作 | `action_start`、`action_stop`、`action_pause`、`action_resume` |
| `status_` | 状态摘要 | `status_next_in`、`status_paused`、`status_waiting_restart` |
| `interval_` | 间隔段落 | `interval_fixed`、`interval_random`、`interval_preset_seconds` |
| `refresh_` | 刷新类型 | `refresh_type`、`refresh_full_page`、`refresh_xhr` |
| `opt_` | 选项行 | `opt_hard_refresh`、`opt_keep_active`、`opt_refresh_limit` |
| `opt_desc_` | 选项副标题 | `opt_desc_hard_refresh` |
| `act_` | 交互行为枚举 | `act_stop`、`act_pause`、`act_restart` |
| `redirect_` | 重定向枚举 | `redirect_follow`、`redirect_canonical` |
| `err_` | 校验错误 | `err_interval_positive`、`err_random_range` |
| `aria_` | 无障碍标签 | `aria_interval_seconds`、`aria_random_min` |
| `xhr_` | XHR 运行期失败（本轮未刷新） | `xhr_not_found`、`xhr_invalid` |

**不复用 ARP 的 key 名**（`keep_active_background`、`interactions_title_opt` 等）：
ARP 的 key 大量是付费/AI/监控语境，且同 key 在不同版本语义漂移过（示例：
`interactions_title_opt` 在 popup 是"用户交互时的刷新行为"，设置页对应的却是"用户交互时的更新行为"）。
新 key 更短、语义唯一。

## 4. 参数替换规范

`chrome.i18n.getMessage` 的占位语法是 **`$1`…`$9`**（*不是* `%1`；写成 `%1` 时 Chrome
原样输出，界面会出现字面的 `%1秒` —— 本轮实测踩到过这个坑），**无命名占位**。
所以：一条文案最多 9 个参数，且参数含义必须写进本表（避免调用处传错顺序）。
带参数的 key 在上表已标注 `$1`/`$2`。

## 5. 与 Chrome 的注意点

- `messages.json` 每个条目必须有 `message`；可选 `description`（给翻译者，本扩展留空）。
- 文件必须是 **UTF-8 无 BOM**；`description` 里不要放换行。
- `default_locale` 必须存在对应目录，否则扩展直接加载失败。
- popup HTML 里 `__MSG_app_name__` 也可用，但本扩展统一走 `t()`（便于运行时切换与测试）。

## 6. 不再需要的东西

ARP 的 `chunks/I18nProvider-*.js`（24MB 级的多语言字典，含 19 种语言）**完全不引入**：
它是 ARP 为独立设置页（`account.autorefresh.io`）准备的语言包。本扩展只有面板，
一套 `messages.json`（约 60 条）足够。
